# Roadmap outline

The framing deck of the Concordance project, six slides on where the tool goes after its first site. The deck is the original, its PDF the preview the build would have converted anyway, and this note its written form; the three sit in one folder and the build groups them into one page.

## What the deck says

1. Today: a static site from markdown repositories. Every note becomes an entity page, every recurring expression a keyword page, every doubt a finding in the build log, never a stopped build; two builds of unchanged sources give byte-identical files.
2. Documents: office documents converted to PDF at publication and cached by fingerprint, transcripts read cue by cue with their speakers pseudonymised before anything else reads them, twin resources recognised as one page with tabs.
3. Contracts: an API note declares its contract, the build imports the operations, each operation note absorbs the operation it names, and a purpose-built viewer renders the contract under the page budget.
4. Quality: a linter where the notes are written, the same checks in the merge request and in the build, a SARIF log in the margin of the diff; the wiki keeps pace with the tool, every check having its rule note.
5. Later: a service beside the command line, with a model query API for the screens that cannot read `model.json` and suggestions reviewed on a screen and recorded in the lock file. Nothing of it exists in this version.
